# 前端整站测试指南

本指南用于在后端、数据库和测试数据准备完成后，完整测试页面、权限、交互、异常和数据一致性。前端仓库不保存测试账号和员工数据。

## 0. 测试准备

先启动小组后端和测试数据库，再在项目根目录执行：

```bash
npm install
npm run typecheck
npm run build
npm run dev
```

打开终端显示的地址。需要恢复测试数据时，使用后端测试库的快照或种子脚本，然后重新运行：

```bash
npm run dev
```

## 1. 测试账号

测试账号、密码和角色由后端测试数据库或部署环境提供，前端仓库不存储真实员工信息。至少准备：

- 一个 `PLATFORM_ADMIN` 技术管理员
- 五类源业务角色账号
- 一个待激活账号
- 一个停用账号

角色必须通过 `sys_user_role` 明确分配，不能根据岗位自动推导。

记录测试结果时建议使用：

```text
编号 | 页面/路由 | 操作 | 账号 | 预期 | 实际 | 通过/失败 | 截图或请求ID
```

## 14. 统一异常行为

- [ ] 401 `SESSION_INVALID` 只跳转一次登录页，并显示登录已失效。
- [ ] 登录接口 401 只显示表单错误，不触发全局退出。
- [ ] 403 只显示一次无权限提示。
- [ ] 400 定位到字段，不弹重复全局错误。
- [ ] 404 关闭或刷新已删除对象。
- [ ] 409 显示明确业务原因。
- [ ] 412 刷新版本并保留用户选择。
- [ ] 429 显示 `Retry-After` 等待时间。
- [ ] 503 提示鉴权服务不可用，不显示成功状态。

## 15. 登录锁定

使用一个启用账号连续输入 5 次错误密码：

- [ ] 每次错误都返回统一的 `LOGIN_FAILED`。
- [ ] 第五次错误后账号进入 15 分钟锁定。
- [ ] 锁定期间输入正确密码返回 429 `LOGIN_LOCKED`。
- [ ] 错误密码不会通过锁定状态泄露账号是否存在。
- [ ] 通过后端测试数据恢复流程清除锁定状态。
